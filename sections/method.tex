\section{ERA: evidence-guided evaluator evolution}
\label{sec:method}

ERA treats evaluator evolution as search over executable programs with a fixed base model.
It separates two decisions: whether a candidate improves the best evaluator, and whether its direction warrants further implementation.

\subsection{Optimization objective and measurements}
\label{sec:runtime}
\label{sec:measurement}

For domain $D$, let $\mathcal{P}_D$ sample an input and then uniformly sample a strict human preference within its candidate group.
With a fixed repeated-scoring protocol, the target is
\begin{equation}
 J_D(\theta)=
 \Pr_{(x,y^+,y^-)\sim\mathcal{P}_D,\,\xi}
 \bigl[\bar{s}_\theta(x,y^+)>\bar{s}_\theta(x,y^-)\bigr],
 \label{eq:objective}
\end{equation}
where $\xi$ includes randomness in the $R$ executions used for each median score.
Each execution is pointwise (Equation~\ref{eq:program}), without access to the opponent or preference label.
The default synthesizer receives specialist findings, reasons, and scopes, but not structured scores or scales (Figure~\ref{fig:runtime}; Appendix~\ref{app:synthesis}).

Search observes a finite-cohort estimate, not $J_D$.
Full-evaluator measurements request $R\geq3$ executions per artifact.
For complete executions on input groups $\mathcal S$ with nonempty strict-preference sets $P_g$, define
\begin{equation}
 \begin{aligned}
 \bar{s}_\theta(x,y)&=\median_{r=1,\ldots,R}s_\theta^{(r)}(x,y),\quad
 z_{gj}=\ind[\bar{s}_\theta(x_g,y_{gj}^+)>\bar{s}_\theta(x_g,y_{gj}^-)],\\
 \widehat J_{\mathcal S}(\theta)&=\frac{1}{|\mathcal S|}\sum_{g\in\mathcal S}\frac{1}{|P_g|}\sum_{j\in P_g}z_{gj}.
 \end{aligned}
 \label{eq:measurement}
\end{equation}
Input groups receive equal weight; predicted ties count as incorrect.
The native development proxy uses one fixed pair per input and need not represent every within-group preference.
Missing executions retain their denominators through coverage and missing-outcome bounds (Appendix~\ref{app:measurement}).

\subsection{Directions and candidate programs}
\label{sec:proposal}

A direction $d$ specifies a correction to the evaluation procedure, motivated by a hypothesis about how it would repair an observed error.
Its implementation may require coordinated changes across $(A,K,V,T,\Pi,G)$.
For example, correcting omission judgments can require finding missing content, assessing its importance, and making that assessment affect the score.
A candidate $C$ is one complete program implementing the direction, not an individual edit.

The agent constructs candidates from inspectable proposal data $\Dprop$, including artifacts, human feedback, and execution traces.
A disjoint sealed subset $\Ddev$ returns aggregate measurements only.
The direction is the unit of continued exploration; the complete program is the unit of selection.
Connected edits share one parent and one measured outcome, so a bundle's gain is not independent evidence for each edit.

\subsection{Candidate acceptance and working-state updates}
\label{sec:search}

Let $B_t$ be the best accepted program and $W_t$ the working program for the active direction.
A new direction starts with $W_t=B_t$; within that direction, the next candidate edits $W_t$ using retained diagnostics.
Every valid, distinct candidate receives the common development measurement.

Define $\Gamma_t(C)$ as the acceptance guard: complete and comparable execution, nondecreasing coverage, and the prespecified stratum-regression check.
Writing $\widehat J_{\mathrm{dev}}(C)$ for the recorded agreement of program $C$, acceptance is
\begin{equation}
 a_t(C)=\ind[\widehat J_{\mathrm{dev}}(C)>\widehat J_{\mathrm{dev}}(B_t)]
 \,\ind[\Gamma_t(C)].
 \label{eq:acceptance}
\end{equation}
A separate predicate $w_t(C)$ determines whether the candidate can be inherited as the next working program:
\begin{equation}
 B_{t+1}=
 \begin{cases} C,&a_t(C)=1,\\ B_t,&\text{otherwise},\end{cases}
 \qquad
 W_{t+1}=
 \begin{cases} C,&w_t(C)=1,\\ B_t,&\text{otherwise}.\end{cases}
 \label{eq:search-update}
\end{equation}
Set $w_t(C)=0$ if required local or development comparisons are missing, incomplete, or incomparable.
Otherwise, $w_t(C)=1$ for accepted candidates, candidates without observed damage, or damaged candidates with fresh, previously uncredited progress and preserved protection cases.
Damage means a local regression or net regression against the parent or best program on sealed development comparisons.
Progress is a newly repaired root error or a predeclared exact trace-field change; neither automatically verifies the hypothesis (Appendix~\ref{app:algorithm}).
Both decisions use the pre-update state, so failed inheritance returns to $B_t$ even if $C$ becomes $B_{t+1}$.

Equation~\ref{eq:search-update} preserves nondecreasing recorded development agreement for $B_t$ while allowing $W_t$ to pass through candidates that do not improve it.
This is a selection invariant, not a guarantee of unseen agreement or statistical significance.

\subsection{Diagnostic continuation and termination}

Depth-first allocation gives the active direction the next editing opportunity, independently of candidate acceptance.
The agent can request diagnostics, submit another implementation, or pause when it cannot propose a different informative test.
The controller enforces working-state eligibility and resource limits, not the agent's interpretation of failure.
Thus, a direction can continue from the prior best program when its latest candidate cannot be inherited.
Diagnostics check whether the proposed behavior occurred and affected the judgment as hypothesized.
Detecting omissions without using their importance in the score would motivate testing that missing step.

Refutation requires results that contradict the hypothesis within its stated scope after relevant implementation alternatives have been examined.
The controller does not automatically adjudicate semantic refutation.
Resource exhaustion leaves an unresolved direction, not a refuted one.

Adaptive reuse makes $\Ddev$ development data, not an independent test.
On normal completion, Train orders eligible candidates; terminal $\Dval$ assesses the frozen shortlist without reranking or edits.
The seed remains if no eligible improvement exists, and independent Test/OOD assessment follows method freeze (Algorithm~\ref{alg:era}; Appendix~\ref{app:boundaries}).
