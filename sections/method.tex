\section{IterEval}
\label{sec:method}

IterEval combines disagreement-based preference mining with depth-first evaluator evolution.
Mining directs limited human feedback toward comparisons on which existing evaluation signals disagree; evolution develops a correction hypothesis through successive testable revisions before branching.
Execution evidence is retained after candidate rejection, allowing unsuccessful implementations to inform the next revision.
A candidate's usefulness as a working program is distinct from the evidence it provides for the active hypothesis.
The search separates \emph{working-state transition}, \emph{direction continuation}, and \emph{global checkpoint selection}.
Train execution evidence drives local search and direction development, while restricted Val feedback governs global retention.

\subsection{Setup and revision space}
\label{sec:problem}
\label{sec:measurement}
\label{sec:runtime}

Starting from a seed evaluator $E_0$, IterEval revises an executable evaluation program $E_\theta$ using human feedback, with the base model $M$ fixed.
The program specifies artifact adapters $A$, rubrics and dimensions $K$, evaluator modules $V$, tools $T$, evidence routing $\Pi$, and fusion $G$.
A revision can change connected components, such as a detector, its route, and the scoring instruction that uses its findings.
It produces a complete candidate program, executed and evaluated as a whole (Figure~\ref{fig:runtime}).

For a task $x$, the evaluator scores each output $y$ separately, without seeing the competing output or human preference.
Within a domain $D$ sharing an evaluation standard, the objective is agreement with human preferences on unseen inputs,
\begin{equation}
 \max_{\theta}\ J_D(\theta),\qquad
 J_D(\theta)=
 \Pr_{(x,y^+,y^-)\sim\mathcal P_D,\,\xi}
 \bigl[\bar s_\theta(x,y^+)>\bar s_\theta(x,y^-)\bigr].
 \label{eq:objective}
\end{equation}
Here $y^+$ is the human-preferred output, $\mathcal P_D$ is the domain distribution, and $\bar s_\theta$ is the score under a fixed repeated-scoring protocol with execution randomness $\xi$.
Before mining, a fixed-seed random split assigns original-input groups from the frozen domain source pool to Train, Val, and Test.
Mining and random-anchor selection operate only within Train.
Val and Test inputs and outputs remain fixed, with compared methods sharing the same split in each run (Appendix~\ref{app:measurement}).
Train exposes artifacts, human feedback, and traces to the optimizer.
Val cases and traces remain sealed; the optimizer receives only the promotion indicator and retained best score.
Test stays locked until search ends and the selected program is frozen (Appendix~\ref{app:measurement}).

\subsection{Disagreement-based preference mining}
\label{sec:mining}

Mining prioritizes disagreements among metrics and judges, while retaining a random anchor to check for errors shared by the available signals.
The Train pool contains pairs $r=(x,y_a,y_b)$ from existing datasets or newly generated outputs.
Post-split output generation for mining is restricted to the assigned Train inputs.
Each signal $j$ yields $u_j(r)\in\{-1,0,+1,\bot\}$: preference for $y_b$, a tie, preference for $y_a$, or unavailable evidence.
Each sign is obtained by comparing that signal's scores using a prespecified tie margin.
Signals sharing a model or underlying metric belong to a source group.
Each signal is either overall or mapped to one or more quality dimensions $q$ from the domain's evaluation standard.
These definitions are fixed before revealing human preferences.

Within each dimension, a source group contributes at most one sign; opposing signs within the group yield abstention.
The dimension's aggregate preference is the sign of the sum of group votes.
We rank pairs by
\begin{equation}
 P(r)=2\sum_q I_{\mathrm{within},q}(r)
      +\sum_q I_{\mathrm{overall},q}(r)
      +I_{\mathrm{tradeoff}}(r).
 \label{eq:conflict}
\end{equation}
The first indicator marks opposing signals from different source groups on dimension $q$; the second marks opposition between an overall signal and a signal on $q$.
The last is one when aggregate preferences disagree across dimensions.
Ties and missing signals never count as opposition.
The fixed 2:1 weighting prioritizes disagreement about the same criterion, while the capped trade-off term prioritizes cross-dimension conflicts.
The score allocates annotation priority to these predefined forms of disagreement.

Before computing mining scores, original-input hashes select the random anchor, keeping outputs from the same input together.
The anchor uses part of the feedback budget.
The remainder is filled by decreasing $P(r)$, with pair identifiers breaking ties.
Signal inventories, tie margins, and anchor size are fixed before selected labels are revealed (Appendix~\ref{app:annotation}).
After selection, we obtain human preferences by reuse or blinded annotation.
Reuse requires the same task and output pair and matching evaluation criteria and annotation protocol, or an explicitly audited harmonization.
Otherwise, annotation supplies new preferences.
Both routes preserve label provenance and missing feedback fields; unselected labels remain hidden.
We evaluate mining by downstream evaluator improvement, not disagreement yield.

\subsection{Depth-first evaluator evolution}
\label{sec:proposal}
\label{sec:search}

The search maintains an exploratory working program $W$, a best program $B$, and an active direction $d$ with diagnostic history $z$.
A direction consists of a hypothesis about an evaluation error and a proposed correction, together with the revisions that test or implement it.
The search is depth-first at the direction level: a failed implementation leads to another test of the active correction before a new direction is opened, unless a direction-ending condition fires.
An edit budget $\Delta$ bounds the number of characters changed from parent to candidate.
Separating $W$ from $B$ allows useful intermediate implementations to accumulate before global retention (Figure~\ref{fig:overview}b).

\paragraph{Semantic contracts make predictions testable.}
A new direction starts from $W=B$.
From Train traces, the agent formulates a correction hypothesis with testable consequences.
Each revision links its edit to that hypothesis through a contract: trace-grounded preconditions, the proposed modification, and predicted postconditions.
The postconditions name targets $T_t$ expected to become correct, contrasts $K_t$ expected to preserve their judgments, and designated intermediate observables $O_t$ with predicted changes.
Each observable identifies a component output field and the cases where it is checked.
Before execution, the agent commits to a repair contract ($T_t\ne\varnothing$) or a scaffolding contract ($T_t=\varnothing$), fixing the applicable transition rule.
Let $g_t^{\mathrm{chg}}$ indicate whether designated observables change relative to the parent, and $g_t^{\mathrm{pred}}$ whether the observed changes match the contract's predictions.
Both checks aggregate over these observables using rules fixed in the run configuration.

\paragraph{Execution evidence guides the next revision.}
Repairing a declared target or a non-target case can yield the same net gain, while zero gain can conceal repairs offset by regressions.
Case-level checks and intermediate observations distinguish these outcomes relative to the contract.
The history $z$ retains prediction outcomes, case differences, and trace pointers, including evidence from rejected candidates, separately from the agent's explanations.
The agent uses this record to choose the next edit or diagnostic probe within the direction.

\paragraph{Working-state transition.}
At step $t$, the agent produces a complete candidate $C_t$ within budget $\Delta_t$ of its parent $P_t=W_t$.
Both programs are measured on the same Train batch $S_t$, containing targets, contrasts, and additional cases.
Let $v_i(E)$ indicate a correct strict pairwise judgment by program $E$ on case $i$.
We compute net gain and, for a repair step, the \emph{target-normalized net gain}
\begin{equation}
 n_t^{\mathrm{tar}}=|T_t|,\qquad
 G_t^{\mathrm{net}}=\sum_{i\in S_t}[v_i(C_t)-v_i(P_t)],\qquad
 \rho_t=\frac{G_t^{\mathrm{net}}}{n_t^{\mathrm{tar}}}\quad(n_t^{\mathrm{tar}}>0).
 \label{eq:target-normalized-gain}
\end{equation}
The numerator counts repairs minus regressions across the whole batch, including collateral effects outside the targets.
We use the declared target count as a reference scope, requiring realized net benefit to be commensurate with that scope.
Contrast outcomes help the agent diagnose overgeneralization, while contrast regressions also enter the net gain.
Repair inheritance uses the output-change check and target-normalized net gain: $g_t^{\mathrm{chg}}=1$ and $\rho_t\geq\eta_1$.
Otherwise, the parent remains.
Predicted-change fulfillment is retained separately as evidence about the proposed mechanism and guides subsequent revisions.
When $g_t^{\mathrm{chg}}=0$, the attempt is recorded as absent behavior and retains both parent and budget.

\paragraph{Intermediate implementation can precede preference repair.}
A scaffolding revision declares no immediate target repair ($T_t=\varnothing$), instead predicting an intermediate observable change intended to support a later repair.
It becomes the next working program when $g_t^{\mathrm{chg}}=g_t^{\mathrm{pred}}=1$ and $G_t^{\mathrm{net}}\geq0$, with the budget unchanged.
For example, a layout detector can first expose overlooked faults without changing scores; a subsequent revision can connect those findings to scoring.
This permits coordinated changes across neutral intermediates.

\paragraph{Direction continuation: adapt the edit budget.}
The controller adjusts the permitted revision size with a trust-region-inspired expand/contract rule~\citep{conn2000trust}.
For repair steps with $g_t^{\mathrm{chg}}=1$, $\rho_t$ below the inheritance threshold contracts $\Delta$; meeting the expansion threshold while using most of the budget expands it.
Otherwise the budget is preserved, including for scaffolding and absent-behavior attempts.
The agent chooses what to change within this allowance using the diagnostic history.
Rejecting a repair candidate therefore need not end the direction.
When contraction takes $\Delta$ below a minimum editing scale, the controller retires the direction and restarts from $B$.
A per-direction step cap bounds repeated absent-behavior attempts.
Agent-requested endings and resource limits are recorded separately.
Here $\Delta$ controls edit size, not confidence in the correction hypothesis.
The complete policy and its relation to trust-region theory appear in Appendix~\ref{app:algorithm}.

\paragraph{Global checkpoint selection: retain improvements separately.}
Periodic checkpoints compare $W$ with $B$ on full Val under the same scoring protocol.
A checkpoint is promoted to $B$ only when its accuracy exceeds the retained score by at least a preset margin.
To restrict feedback from repeated Val access, the optimizer receives only the promotion indicator and retained best score~\citep{blum2015ladder}.
Checkpoint outcomes update retention only, leaving $W$, $\Delta$, and direction continuation unchanged.
The working program can therefore remain below the best Val score while its correction is developed.
After a final checkpoint, the best program is frozen and compared with the seed once on Test.
Train guides adaptive exploration, Val guides adaptive retention, and this held-out Test comparison supplies the reported generalization assessment.
